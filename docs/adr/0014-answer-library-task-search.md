# ADR-0014：已验收答案库与 task_search（task output 复用）

- **状态**：已接受
- **日期**：2026-10-15

## 背景

任务池的交付物天然持久化：deliverable 摘要（PG，≤4000 字快照）、完整
轨迹（checkpoint / run_events，TTL 90 天）、产物文件（OSS 归档）、验收
状态（`accepted_loop_id`，验收后不可变）。叠加全公司共享可见（QA-5/QA-9）
与"做过了就不该重做"的诉求（2026-10-15 设计讨论），任务池的定位从
"待办队列"升级为**公司已验收答案库**。缺的是检索入口与复用规则。

与"业务数据零落地"（设计文档 §4）的关系：已验收交付是**带来源、带验收人、
带时间戳、不可变**的公司档案——不是源系统的影子库，也不是 agent 私有缓存。
红线不变，本条是对其的释义补充。

## 决定

1. **三层资产定位**：方法层（agent 定义 / skills / facts —— know-how
   固化）+ 答案层（已验收交付 —— 结果复用）+ 轨迹层（thread /
   checkpoint / run_events —— 审计下钻）。
2. **task_search 只读检索**：fleet 工具组新增 `task_search`（runner 侧），
   底层 = 控制面 `GET /api/tasks/search` 端点（FAP read 能力的内侧暴露）。
   MVP 用 PG ILIKE / pg_trgm 检索 input + deliverable + 评论，量级上来后
   再评估向量检索。返回 task_id / 输入摘要 / 验收状态 / 交付时间 /
   交付超链接 / 认领者；**已验收优先排序，状态必标**——已验收 =
   公司答案，已交付未验收 = 草稿（QA-20）。
3. **引用型交付是一等交付**（QA-22）：agent 命中后回复"与已验收
   task #N 相同"并给出 #N 的超链接，即为当前 task 的有效 output；
   命中时必须先问用户"该交付日期的 output 直接使用，还是重新取数跑
   最新"（QA-21）；用户认可即按正常验收动作通过（验收权仍属
   发起者/admin，见 ADR-0012 第 8 条）。
4. **无失效概念**（QA-23）：output 之间不存在有效/失效关系——每个
   output 都是带时间戳、对当初那个 task 的回答。新 task 搜出多个相似
   答案则全部列出，由用户判断哪个对当前 task 有效，判断即验收。
   不建 `superseded_by` 之类的失效字段。
5. **两个入口**：执行时入口（agent 经 task_search 主动检索）MVP 先行；
   创建时入口（人/Codex 建 task 时提示相似已验收任务）紧随其后，
   复用同一 search 端点。
6. **复用决策永远属于人**：agent 不得自行把旧答案当新交付回放而不经
   验收（与 ADR-0010 强制验收一致）。

## 后果

- 正面：做过了就不再重做——token 与人力双省；答案复用全程可审计
  （task→task 引用链）；验收闸不被架空；只读检索 + 不可变交付在
  并发下天然安全。
- 负面/约束：答案库质量上限 = 验收纪律质量（验收权权威化依赖 P4
  身份归因落地，ADR-0012/0013）；时效敏感数据的复述风险由 QA-21
  "命中即询问用户"兜底，而非系统强制。
- 实施列入 P3c，与 ADR-0012 原子性修复同批。

## 已考虑的备选

- **agent 私有记忆回放旧答案**：否决——违反业务数据零落地、绕过验收、
  归因断裂（2026-10-15 设计讨论结论）。
- **结构化 as-of 日期字段 + 系统自动判时效**：否决（QA-21）——交付
  日期已有（`delivered_at`），时效判断交给人。
- **`superseded_by` 失效标记**：否决（QA-23）——output 无失效概念，
  多候选列出由用户判断。
