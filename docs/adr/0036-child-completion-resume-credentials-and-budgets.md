# ADR-0036：子任务完成续跑、共享凭据句柄与执行预算

- **状态**：已接受
- **日期**：2026-11-02

## 背景

真实协作中，指挥官会并行创建子任务，但子任务交付后需要人工发送“继续整合”，因此无法形成自主闭环。检索 Agent 还需要复用同一业务系统授权，直接传递密码或私有路径又会把秘密写入 Task 与记忆。另有子任务输出过长、重复检索和数值计算错误，单靠 Soul 约束无法形成可执行边界。

## 决定

1. **子任务全部终态后唤醒父 Loop**：`deliver_loop` 检查直接子 Task，全部进入 `success/error/rejected` 后，将各子任务真实 OUTPUT 或错误按预算压缩为系统修正意见，唤醒最新一个已 `delivered` 的父 Loop。复用现有 `returned → 同 Thread 续跑`，不另建消息总线；正在执行、已 returned 或已验收的父 Loop 不重复触发，409 状态冲突不重复唤醒。
2. **不隐藏等待问题**：父任务自然在子任务完成后交付时，不强制增加版本。测试必须区分自然完成与提前交付后自动续跑，验收以父 Loop `version ≥ 2` 且再次 `delivered` 为准。
3. **统一凭据句柄**：Timeline 只通过 `timeline.meta/boards/items` 只读 operation 访问。`timeline-read` 的 base URL、密码和短期 token 由 Gateway 保管与注入；Agent 只获得数据响应，不获得秘密正文。凭据轮换仅人工完成，专用工具组与出站白名单最小化，不开放任意 URL。
4. **子任务预算显式化**：`agent_spawn` 可携带 `recursion_limit` 与 `summary_chars`，随 Loop 持久化并传递 Runtime。完整 OUTPUT 独立保存，父级唤醒按 `summary_chars` 压缩，避免把长文和重复输入转发给父上下文。
5. **数值校验确定性化**：合计、守恒和占比由代码计算，模型负责选择与解释，不依赖模型自行修正算术。
6. **不自动扩张**：自动唤醒不得重复派发相同子任务；预算、摘要和凭据句柄不授权生产写入。Timeline 句柄未配置时必须明确报未配置，不得伪造已激活。

## 后果

- 正面：提前交付的父任务可以自主完成后续组装；统一授权不再依赖秘密复制；成本、摘要和数值正确性都有可测试边界。
- 负面／约束：只覆盖直接子 Task，嵌套后代逐层唤醒；多父 Loop 竞争时只唤醒最新 delivered Loop，避免重复消耗。临时测试 Gateway 的预算与回调地址必须与 Control Plane 对齐，否则实测会走到旧进程。
- 实施证据：专项测试覆盖终态门闩、重复唤醒、凭据不泄露、预算传递与算术校验；真实端到端复测父 Loop 自动进入 `version=2` 并完成最终 OUTPUT。

## 已考虑的备选

- **指挥官持续轮询**：否决，增加 Token、延迟与提前结束风险；仅在必要状态读取时使用。
- **阻塞式 `agent_spawn`**：暂缓，长任务会占用父 Run 并放大恢复复杂度；当前采用交付事件驱动续跑。
- **把凭据放入共享记忆或子任务说明**：否决，便利不能抵消秘密扩散；统一共享使用权限，不共享秘密正文。
- **只限制输出字数**：不足，必须同时限制执行步数、父级摘要和数值校验。
