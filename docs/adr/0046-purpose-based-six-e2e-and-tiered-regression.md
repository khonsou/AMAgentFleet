# ADR-0046：按验收目的组织六项基础 E2E 与分层回归

- **状态**：已接受
- **日期**：2026-11-02
- **补充**：细化 ADR-0045 的集合覆盖、single／multi 对照和重复稳定门，避免把对照协议机械扩张为全量测试矩阵。

## 背景

首轮 `platform-basic-v1` 实测中，每个 case 都运行 single／multi、每个 case 都重启完整 Fleet，并在行为确认前重复全量回归，产生不必要的环境与模型开销。简单时间题的多 Agent 运行没有新增验收信息，反而暴露完整能力面上下的 Token 放大。需要保留可比较的北极星，同时将基础 E2E 限定为能覆盖核心风险的最小集合。

## 决定

1. **基础 E2E 固定为六项**：`core-v1/single`、`core-v1/multi`、`time-now-v1/single`、`multi-echo-v1/multi`、`external-info-v1/single`、`external-info-v1/multi`。新增 case 必须说明覆盖的新风险，不能用重复模式凑数量。
2. **按目的声明模式**：集合 case 使用 `required_modes`、`candidate_mode` 和可选 `comparison_group`。只有声明对照的 case 才需要 single 基线；非对照 case 只运行能证明目标能力的模式。`time-now/multi` 与 `multi-echo/single` 不进入常规基础列表。
3. **汇总区分平台通过与对照改善**：候选 SZ-VSR 按各 case 的 `candidate_mode` 分层汇总；single／multi delta 只在相同 `comparison_group` 的可比 case 上计算。覆盖率按六项必需运行计算，不再要求每个 case 都有两种模式。
4. **一轮共享一个环境**：六项在同一 Fleet 环境顺序执行，结束后统一回收。基础设施未就绪必须停止，不得在故障环境中继续消耗模型预算。
5. **测试分层**：编码阶段只跑相关离线测试；行为确认后运行六项 E2E；候选准备接受时再跑控制面及其他全量回归。`pass^k` 用于修改过的 case 或正式发布候选，不在每次探索中机械重复全部 case。
6. **能力最大化不等于全量上下文注入**：保持 `inherit_all` 和运行时能力可发现、可调用，另行优化按 Goal 水合工具 Schema、Provider 详情和技能说明。不得通过裁剪注册 Agent 的权限来降低 Token。
7. **成本口径先对账**：Loop tokens 与线程 token_usage 出现差异时，先审计重试、内部调用和汇总规则；不得通过提高预算或删除失败运行制造改善。

## 后果

- 正面：基础列表覆盖单 Agent 对照、最简全流程、多 Agent 自动唤醒、普通 Agent 与指挥官的动态外部能力调用；环境启动和无效模式显著减少。
- 负面／约束：集合汇总需要区分候选通过与可比基线，不能再用每个 case 都有 single／multi 的简单假设。非基础列表的专项实验仍可按明确假设单独执行。
- 本批只改变测试组织与执行口径；全量回归是否通过必须在候选确认后另行验证，不得由六项 E2E 推断。

## 已考虑的备选

- **继续所有 case 都跑两种模式**：否决，信息增益不足且放大 Token 与环境成本。
- **只保留一个端到端场景**：否决，无法分别定位时间、自动唤醒、外部能力和多源协作回归。
- **通过限制 Agent 能力降低 Token**：否决，违背运行时能力最大化原则；应优化按需上下文水合。
