# ADR-0015：人与 Agent 同权的任务验收

- **状态**：已接受
- **日期**：2026-10-27
- **取代**：ADR-0010 第 3 条“验收人 = task 创建者”；ADR-0012 第 8 条中 accept/return 的“创建者/admin”限制；ADR-0014 第 6 条“复用决策永远属于人”的验收权限限制

## 背景

共享任务池要求人与 Agent 同构协作，但旧决策把验收权限定为任务创建者或 admin，既无法让内部 Agent 完成独立验收，也无法让通过 FAP/A2A 登录的第三方 Agent 参与验收。需要以简单、统一的权限规则替代人类特例。

## 决定

1. **任何已识别的人或 Agent 均可验收**：内部 Agent、Console 用户、通过 FAP/A2A 以有效 PAT（write scope）登录的第三方 Agent，调用相同的 accept/return 端点、驱动相同状态机；不限制必须是创建者、admin 或其他执行者。
2. **验收动作保持任务级语义**：采纳使 task → done 并绑定 accepted_loop_id；退回只作用于对应 loop。关闭作废不属于本 ADR 放开的验收动作。
3. **同一动作、同一审计**：审计记录 task、loop 与 actor。FAP/A2A 请求以已验证 PAT 身份覆盖 body 自报 author；内部 Agent 与开发态 Console 沿用现有身份来源，不另建 reviewer 实体或 Agent 专用验收流程。
4. 页面统一称“交付验收”，它是 task 内的动作区，不是新的 Agent 或 Thread 实例。

## 后果

- 正面：人与 Agent 的验收规则、API 和状态流转一致；第三方可直接参与共享池协作；无需引入评审专用数据模型。
- 负面/约束：开放验收依赖透明池与审计追责，而非创建者权限；PAT 写权限即包含验收能力。关闭作废的权限不受本 ADR 影响。

## 已考虑的备选

- 仅创建者/admin 验收：否决，违背本轮人与 Agent 同权协作的目标。
- 新增 reviewer Agent 类型及独立验收状态机：否决，增加概念与实现复杂度；reviewer 只是执行验收动作的普通 Agent。
- Agent 只能评审、人才能最终验收：否决，形成人类特例，无法覆盖自动化与第三方协作场景。
