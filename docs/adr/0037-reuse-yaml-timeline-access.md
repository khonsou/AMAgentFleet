# ADR-0037：Timeline 访问复用现有 YAML 能力，否决专用代理层

- **状态**：已接受
- **日期**：2026-11-02

## 背景

ADR-0036 在实现子任务自动唤醒时，同时增加了 `timeline-read` 凭据句柄、专用 operation、代理路由与激活脚本。复核后确认：Timeline 的读取能力已经由现有 Agent YAML（`mcp_plugins`、`egress`）与 Gateway 提供，新增一套平行访问层只会增加协议、权限和维护成本，不能解决新的业务问题。

## 决定

1. **Timeline 访问继续复用现有 YAML 与 Gateway 能力**，不为 Fleet 新增 `timeline-read`、专用代理路由、专用工具组或激活流程。
2. **撤回平行实现**：删除 Timeline 专用 Python 代理、协议 surface／operations、激活脚本和 `fleet:timeline` 工具组；Timeline Agent 恢复 `mcp_plugins: [http]` 与既有 egress 配置。
3. **保留真正通用的改动**：子任务完成自动唤醒、`recursion_limit`、`summary_chars`、确定性数值校验和评分持久化不受影响。
4. **不再新增访问能力缺失项**：后续迭代不设置“配置 Timeline 专用句柄”任务。已生成的该建议标记为 `rejected`；安全复核只关注既有授权与记忆边界，不虚构新的接入工作。
5. **ADR-0036 的凭据句柄部分由本 ADR 取代**。自动唤醒与执行预算部分继续有效。

## 后果

- 正面：减少重复协议和权限面，保持现有 Timeline 接入方式与运维认知一致，避免为同一能力维护两套实现。
- 负面／约束：如果未来出现现有 YAML／Gateway 无法表达的新授权需求，必须另写 ADR 证明缺口，不能默认重新引入专用代理。
- 数据：已创建的句柄配置不作为运行依据；不做破坏性数据删除。

## 已考虑的备选

- **保留专用句柄作为统一授权抽象**：否决，当前已有等价能力，新增抽象没有证明净收益。
- **继续开发并激活专用代理**：否决，扩大代码与评审范围，且与本次自动唤醒目标无关。
