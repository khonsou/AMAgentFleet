# ADR-0033：风险分级确认与确认后立即释放界面

- **状态**：已接受
- **日期**：2026-11-01

## 背景

ADR-0017/0031 要求所有写操作明确确认。实际使用中，普通 Agent 消息与删除、凭证、外部连接操作共用阻塞式弹窗：每次对话都被打断，弹窗还等待 Agent 完整回复才关闭，混淆了“确认发送命令”和“等待执行结果”，影响正常协作。

## 决定

1. **风险分级**：普通写操作由当前按钮／表单动作直接确认，不额外弹窗；`confirmation: high_risk` 的操作才展示确认框。初始高风险范围包括 Agent 配置替换或销毁、Task 关闭、Loop 恢复重跑、Thread 销毁、Run 取消、MCP 写入与重载、PAT 吊销。`human_only` 仍只由人类 GUI 完成并需要确认。
2. **幂等不降级**：普通写操作仍携带 `confirmed: true` 与唯一幂等键，服务端继续校验 operation、写属性、actor、human-only 和 secrets。FAP／Agent 工具的写确认语义不随 GUI 弹窗策略改变。
3. **确认后立即关闭**：高风险确认只代表同意发送命令。弹窗在点击确认后立即关闭，执行在后台继续，结果与错误由调用页面独立呈现，不再等待 Agent 回复后才释放界面。
4. **运行操作不全局锁等待**：`threads.create`、`threads.send`、`runs.wait`、`runs.stream` 不把全局 `busy` 用于长时间 Agent 执行；各页面用自己的发送态防止重复提交。
5. **协议声明风险**：风险级别登记在 `fleet-ops-protocol.json`，前端不得另建一套风险名单。测试覆盖普通操作免弹窗、高风险确认前不发送、确认后立即关闭以及慢响应场景。

## 后果

- 正面：普通协作不再被反复打断，高风险操作仍有明确保护；确认与执行结果解耦，避免界面长时间锁定。
- 负面／约束：操作清单需要维护风险级别；后台错误必须回到页面可见区域，不能依赖已关闭的弹窗展示。
- 兼容：operation ID、后端写校验、幂等和审计不变；只调整 GUI 的确认呈现和等待策略。

## 已考虑的备选

- **所有写操作继续弹窗**：否决，正常 Agent 对话被过度打断。
- **完全取消高风险确认**：否决，删除、凭证和外部连接仍可能造成不可逆或高影响副作用。
- **确认框等待执行完成**：否决，把确认发送与等待结果错误耦合，长任务会锁死界面。
- **按页面硬编码风险名单**：否决，会产生协议与页面分叉；风险必须来自统一操作清单。
