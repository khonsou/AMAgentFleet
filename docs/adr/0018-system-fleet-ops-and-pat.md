# ADR-0018：系统内置 Fleet 操作 Agent 与统一 PAT 鉴权

- **状态**：已接受
- **日期**：2026-10-28

## 背景

ADR-0017 规定由默认注册的 `fleet-ops-01` 执行 Fleet Operations Protocol，但实现仍以 Agent 名称白名单作为授权依据。该 Agent 可以被普通 Registry API 修改、停止或删除，其凭证也可以被普通 PAT 管理操作撤销，导致全局浮窗仍然存在、执行能力却静默失效。同时，本地 Agent 与第三方 Agent 走不同授权路径，无法形成一致、可验证的权限边界。

系统需要保证浮窗对应的执行身份持续可用，同时保留版本化部署升级能力；还需要在不把原始 PAT 暴露给 Runner、Thread、日志或 Agent YAML 的前提下，让本地与第三方 Agent 接受同一套 PAT／FAP 鉴权。

## 决定

1. 将 `fleet-ops-01` 定义为系统内置 Agent。普通 Registry API 禁止以该名称创建、修改、删除、停止或启动；页面配置只读并隐藏生命周期操作。版本化部署脚本可直接调用 Registry 部署原语升级，系统锁不等于代码不可维护。
2. 为其配置身份固定为 `fap:system:fleet-ops-01`、scope 固定为 `read+write` 的系统 PAT。普通签发、吊销与删除路径不得冒用或操作系统身份，不提供降权；保留经人工确认的轮换，轮换不回显原始 token。
3. 本地浮窗执行代理与第三方 Agent 统一经过 PAT／FAP 鉴权。移除 ADR-0017 中按 `agent_name` 判断调用权限的白名单，不允许回退到 `lead_agent` 或其他隐式身份；`fleet:ops` 工具组只控制工具可见性，PAT scope 负责授权，operation ID 白名单、写确认和 human-only／secrets 护栏继续有效。
4. 原始系统 PAT 仅由控制面的服务端凭证执行代理使用。密文与 PAT ID 存入 PG，本地开发加密密钥存放在不进 git 的独立密钥文件，生产通过 KMS 适配接口提供；执行代理解密后在服务端注入 Authorization，再调用实际操作，凭证不得进入 Runner 环境变量、Thread、日志、审计正文或工具响应。
5. 本 ADR 取代 ADR-0017 第 2 条中的“其他 Agent 不继承该权限”及专属名称授权语义；协议覆盖性、写确认与秘密隔离继续遵循 ADR-0017，凭证服务端注入与最小暴露继续遵循 ADR-0005。

## 后果

- 正面：全局浮窗的执行身份和权限可长期保持一致；本地与第三方调用具有同一授权口径；删除、改配和撤销不再造成隐性故障；人工轮换不暴露凭证。
- 负面／约束：控制面新增系统凭证 Vault 和执行代理，成为重点加固与审计组件；部署和测试必须提供独立密钥；系统 Agent 的日常变更必须走明确的版本化部署路径。
- 安全边界：系统 PAT 具有高权限，但执行代理仍只能访问协议登记的 operation，所有写操作仍需明确确认，human-only 操作与非空 secrets 请求仍被拒绝。

## 已考虑的备选

- **继续锁定 Agent YAML，但保留名称白名单**：否决，名称不是可验证的授权凭证，且本地与第三方权限语义仍不一致。
- **把 PAT 写入 Agent YAML 或 Runner 环境变量**：否决，违反 ADR-0005，扩大 Thread、日志和 checkpoint 的泄漏面。
- **禁止一切升级与轮换**：否决，会把可用性保护变成不可维护；采用部署专用升级路径与人工轮换。
- **浮窗不可用时自动切换指挥官 Agent**：否决，隐式 fallback 会改变权限主体并掩盖配置故障。
