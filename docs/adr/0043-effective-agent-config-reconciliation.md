# ADR-0043：版本化 Agent 全量配置对账与 inherit-all 重置

- **状态**：已接受
- **日期**：2026-11-02

## 背景

实际出现 YAML、Registry 与 Gateway 三套配置同时漂移：文件声明通用 HTTP 能力，Registry 保留旧哈希，Gateway 则继续使用旧工具白名单和空插件列表。另一个独立问题是 YAML 删除字段后，部署的增量更新把缺省解释为“保留旧值”，因此旧白名单无法清除。

仅修复某个 Agent 或某个外部网站不能消除这类问题。必须统一版本化配置的部署与重置语义。

## 决定

1. **启动时全量对账**：Control Plane 启动时逐个同步版本化 YAML 到 Gateway，更新 Registry 哈希与配置版本，并统一重渲染 MCP 出站配置。运行时动态注册的 Provider 不在版本化目录，不受该对账影响。
2. **部署包是完整能力声明**：RuntimeAdapter 对 `tool_groups`、`mcp_plugins`、`allowed_subagents`、`skills` 的缺省字段显式归一化为 `null`，不得把缺省解释为保留旧配置。
3. **`null` 与空数组语义分离**：`null = inherit all`；`[] = 显式零能力`。Gateway 更新时必须允许用 `null` 清除旧白名单，不能用 `[]` 代替，否则会错误变成零工具。
4. **生效能力必须可验证**：外部调用前先核对 YAML 哈希、Registry 配置版本和 Gateway 实际字段；不能只根据 YAML 或 Agent 自述判断能力已经生效。协议级验证与 Agent 实例级最小任务验证分开记录。
5. **不采用业务补丁**：修复只涉及通用部署、配置和能力语义，不新增任何第三方网站专用流程。

## 后果

- 启动会执行更多配置同步请求，但能避免长期运行不可见的配置漂移；重复同步不会无意义增加配置版本。
- 用户运行时手工修改的版本化 YAML 仍按同一来源对账；未注册为版本化文件的动态 Provider 不被覆盖。
- 对历史运行中使用的旧配置，只通过新任务的实际配置与输出证明修复，不改写历史交付或伪造其当时能力。

## 验证

- 单元测试覆盖缺省归一化、null 重置、全量稳定顺序对账和 MCP 非敏感 env 传递。
- 真实协议验证与 Agent 实例最小只读任务验证通过，且输出包含真实状态、数据与配置证据，不以 blocked 冒充成功。
