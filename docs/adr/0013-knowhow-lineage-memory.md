# ADR-0013：know-how 谱系与记忆治理（共享池场景）

- **状态**：已接受
- **日期**：2026-10-15

## 背景

共享任务池的核心价值路径是 know-how 双通道固化（2026-10-15 设计讨论，
QA-17/18/19/24）：员工重复完成同类任务后注册专精 agent 固化方法
（通道一：A 建、B 用）；执行过程中的事实/技能自动沉淀（通道二：
deermem facts + skill_evolution）。

需要拍板的问题：

1. 固化资产的**谱系**：一个 agent 是从哪些 task 的哪几次人工交付里长出来的，
   现在没有任何记录——know-how 资产无法溯源、无法衡量。
2. **per-agent 记忆在并发/竞争场景的语义**：deermem 是跨时间接力（先完成的
   loop 提炼 facts 落盘，后启动的同 agent 会话注入），不是运行中实时共享；
   同一 agent 的两个竞争 loop 存在"先完成者的经验注入后启动者"的串供窗口。
   QA-18 决议：不同任务间的记忆共享是 know-how 复利来源，竞争场景的串供
   若提升 output 质量则可接受——维持现状。
3. **身份归因**：员工的 Codex 经 FAP PAT 操作 fleet 时，审计必须能回答
   "这是谁的 Codex"（QA-24）。

## 决定

1. **谱系字段**（QA-17）：agent YAML `metadata` 增加可选
   `derived_from_tasks: [int]`——本 agent 从哪些 task 的人类交付固化而来；
   Console 注册页提示填写，不强制。`owner` 维持必填。
2. **记忆维持现状**（QA-18）：deermem per-agent 跨任务共享，**不引入**
   "竞争期只读"等运行时门控；PK 场景的经验注入视为质量提升而非污染，
   不做隔离。
3. **沉淀内容约定（非强制）**：注册模板与 soul 建议 facts 只沉淀
   方法/口径/偏好，不沉淀任务结果数据（"业务数据零落地"红线在记忆侧的
   释义）；高敏 agent 关 `memory_enabled`（已有机制，见 AGENTS.md）。
4. **技能沉淀维持现状**（QA-19）：`skill_evolution` 沉淀的技能写完即
   全局可见（静态扫描 + moderation 模型双闸已在线），注册即全局可用，
   不设晋升评审。
5. **PAT 绑定员工**（QA-24）：FAP PAT 签发时强制绑定当前登录员工身份，
   审计以映射后的员工身份为准——谁的 Codex 在操作 fleet 必须可查。
   实施依赖遗留 QA-2（IdP 选型）与 P4 OIDC 落地，落前排期见设计文档 §9。
6. **复用度量**：per-agent"被领取次数 / 交付采纳率"作为 know-how 资产的
   客观指标，纳入 Console（与 P4 成本台账一并实施）。

## 后果

- 正面：know-how 资产有谱系可溯（谁的方法、从哪几次人工交付固化、
  被复用多少次、采纳率如何）；记忆通道不设闸，复利最大化；
  治理成本为零（约定式）。
- 负面/约束：facts 自动提炼仍可能混入敏感/结果性信息（AGENTS.md 已
  警告），依赖模板约定与高敏场景关停兜底；PK 公平性明确让位于产出
  质量（QA-18）。

## 已考虑的备选

- **竞争期 facts 只读的运行时门控**：否决（QA-18）——deermem 自动提取
  按 run 门控需改底座；串供已确认为可接受。
- **每 thread 记忆独立**：否决——杀掉 know-how 沉淀通道，与系统定位
  （agent 越做越强、A 建 B 用）直接矛盾。
- **技能"先 per-agent 生效、评审后晋升全局"**：否决（QA-19）——双闸
  已够，晋升机制徒增治理环节。
