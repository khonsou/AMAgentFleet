# Fleet Console 全页面信息表达 Review

- 日期：2026-10-30
- 代码基线：`main` / `origin/main`，提交 `9dc2d6bedc0a8bc3e71cbbbc7f3f012a53e4a710`
- 范围：7 个业务页面、登录门与 OAuth 回调、全局导航、Fleet 操作助手、共享状态与消息组件
- 方法：依据当前路由、页面渲染代码、消息规整逻辑和共享样式逐页静态审查
- 约束：只优化信息表达与呈现，不改变业务功能、API、任务流程、权限或数据语义
- 本轮交付：仅 review 报告；未修改页面代码

> **确认修订（优先级高于后文旧表述）**：保留 `Subagent`、`YAML`、`LOOP`、`PAT`、`OUTPUT`、`Thread` 等既有术语，不另造中文叫法。后文如出现“子 Agent”“执行轮次”“会话”“最新输出／最终交付”等建议，实施时分别统一为 `Subagent`、`LOOP`、`Thread`、`OUTPUT` 及其英文限定词；技术标题以简洁和全站一致为准，不强行中文化。

## 1. 总体结论

当前问题不是信息不足，而是**所有信息都以相近的字号、颜色和密度同时出现**，导致用户难以快速回答三个问题：

1. 我现在需要处理什么？
2. 当前结果或异常是什么？
3. 我应该点击哪里继续？

主要成因：

- 同一对象在卡片头、卡片正文、底部链接中重复出现。
- 页面标题、面板标题、状态、元数据、技术标识同时争夺注意力。
- 中文、英文和内部架构术语混用，同一状态在不同页面有不同名称。
- 技术细节默认展开，真正需要行动的“待领取、待验收、异常”反而不够突出。
- 长文本和 JSON 没有统一策略：有的直接铺展，有的内部滚动，有的被静默截断。
- 有意义的标题也使用 10px、低对比度的装饰性 `silk` 样式，视觉层级偏弱。

建议全站统一为以下信息优先级：

> **待办动作／异常 > 任务或交付结果 > 对象名称与主状态 > 时间、Token 等元数据 > ID、模型来源、Run、Checkpoint 等技术细节**

优化目标不是单纯“删字”，而是：**主路径更短、重点更强、细节仍可查看、状态表达更准确。**

## 3. 全站统一规范

### 3.1 名称与术语

建议建立单一文案表，不再由各页面自行拼接状态名称。**Subagent、Task、LOOP、Thread、OUTPUT、YAML、PAT 等既有术语直接保留，不另造中文译名。**

| 当前混用 | 建议统一 | 说明 |
|---|---|---|
| 任务实例看板、任务实例池、任务实例、Task 实例 | **Task 看板、Task** | “实例”不必每次出现；ID 统一为 `Task #123` |
| task #、TASK # | **`Task #123`** | LOOP、Thread 同样统一大小写 |
| loop、LOOP、执行轮次 | **LOOP**，ID 用 **`LOOP #21`** | 不另造中文术语 |
| Thread 实例、会话实例、工作会话、会话日志 | **Thread** | 列表页用“Thread 列表”，详情页用“Thread 详情” |
| Subagent、子 agent | **Subagent** | 保留既有术语；只有确需区分角色时才显示“指挥官” |
| 待分配、待领取、开放任务、未认领、开放中 | **待领取** | 筛选、状态、领取区统一使用用户要执行的动作 |
| 认领、领取 | **领取** | 按钮统一为“领取”，选择器为“选择领取者” |
| 待确认、待验收 | **待验收** | 与“采纳交付／退回”动作一致 |
| 已验收、已终结、完成 | **按真实语义区分** | 已采纳才是“已验收”；人工关闭是“已关闭”；无法区分时短期统一用“已结束”，不能混称 |
| 已打回、退回 | **已退回／退回** | 状态与按钮保持同一词 |
| 最终输出、当前输出、最终交付、交付内容 | **OUTPUT** | 需要区分时用 `FINAL OUTPUT`、`CURRENT OUTPUT`、`OUTPUT SNAPSHOT` |
| Token、token、tok、TOKENS CUM | **Token**；总计用**累计 Token** | 数值仍可用 `12.4k`，不要在每行重复多种单位写法 |
| cron 触发 | **定时任务** | 技术配置中仍可保留 `cron` |
| owner | **负责人** | 与成本中心分行展示，避免 `owner / cost center` 混排 |
| 保存并部署、创建并部署、派发、指派并发起 | 按动作统一为**保存配置、创建 Agent、创建 Task、指派并创建** | 避免同一动作在不同页面使用不同动词 |

原始状态值可以继续用于调试，但不应作为主要 UI 文案：

- `registered` → `已注册`
- `running` → Agent 用“运行中”，Task／Run 用“执行中”
- `success` → `已完成`
- `queued` → `排队中`
- `dispatched` → `已派发`
- `error` → `异常`

### 3.2 中英文与面板标题

当前大量标题同时重复英文和中文。优化目标是**每个标题只表达一次，并保留既有技术术语**，而不是把英文术语强行翻译成中文。

建议：

- **页面主标题只保留一个清晰名称。**
- **Subagent、Task、LOOP、Thread、OUTPUT、YAML、PAT 等保持英文。** 普通动作和状态仍使用简洁中文。
- `MODULE 01`、`FLEET BOARD` 等装饰信息可保留在全局导航，不必在每个详情页重复。
- 面板数量直接写 `3 个 Task`、`2 份交付`，不再重复多种对象名称。

推荐标题：

| 当前 | 建议 |
|---|---|
| `NEW TASK INSTANCE / 发起任务实例` | `发起 Task` |
| `REGISTRY AGENTS / 配置面 · 全员可见` | `全部 Agent` |
| `AGENT DEFINITION / Agent 定义 · YAML` | `Agent 配置 · YAML` |
| `TASK INSTANCES / 关联任务实例` | `关联 Task` |
| `会话实例日志 / THREAD LOG` | `THREADS` |
| `MESSAGES / 会话与任务流` | `MESSAGES` |
| `RUNS / 生命周期记录` | `RUNS` |
| `TASK INSTANCE / 任务实例输入` | `Task 输入` |
| `LOOP INSTANCES / 领取、执行与交付` | `LOOP` |
| `COMMENTS / 人机共用协议` | `COMMENTS` |
| `MODELS / 模型与独立 API KEY` | `模型配置` |
| `PAT / 现存令牌` | `PAT 列表` |

### 3.3 字号、颜色与重点

当前 `.silk` 为 10px、弱色、宽字距，但承担了大量真正的面板标题。建议将“装饰丝印”和“功能标题”分开：

- 页面 H1：22–24px，`font-semibold`。
- 卡片／面板标题：12–13px，`font-medium` 或 `font-semibold`，使用 `ink` 或 `ink-2`。
- 任务、会话、交付标题：14–15px，确保是各自卡片的第一视觉落点。
- 正文：13px；辅助说明：12px；技术元数据：11px。
- `silk` 只用于模块编号、刷新频率、装饰性英文，不再用于重要标题和错误信息。
- `ink-3` 不承载关键状态、空态原因或操作提示；必要信息至少使用 `ink-2`。
- 主任务标题不必使用点状下划线；点状下划线保留给次要内联链接。
- 呼吸闪烁只保留给“正在执行”。“待领取、待验收、已退回”使用稳定 amber，避免多个区域同时闪烁。
- AI 回复和交付内容不必整卡使用绿色底。建议中性面板＋绿色小标识，把绿色留给“成功、已采纳、可用”。
- 错误统一红色，成功统一绿色，警告统一 amber，主操作统一 signal 橙；不要再混用 sky blue 与另一套 `green-600`。

### 3.4 说明文字

统一采用“**标题说对象，正文说动作，细节放辅助说明**”：

- 删除重复解释页面定位的句子，尤其是“请到某页管理”“备用查询”“全员可见”“YAML 一等公民”。
- 快捷键只在输入区出现一次：`Ctrl / ⌘ + Enter 发送`，不要同时放在面板头和 placeholder。
- placeholder 只写示例，不承担字段名称和完整操作说明。
- 技术实现名词不进入主文案：`水合`、`agents_api`、`config_version +1`、`人机共用协议`、`P4`、`ADR-0011`。
- 错误提示先说用户可理解的结果，再提供可展开的技术详情。
- 空状态、加载状态、请求失败必须分开，不能共用一个“暂无数据”。

### 3.5 时间与元数据

- 列表时间优先显示相对时间，如 `3 分钟前`、`昨天 14:20`；完整时间放 `title`。
- 需要绝对时间时，统一 `MM-DD HH:mm`；跨年时显示年份。
- 首页只显示 `HH:mm:ss` 会让跨天任务产生歧义，应至少包含日期。
- ID、来源、Token、模型选择者、同步时间等不应与任务标题同级。
- 次要技术信息可收进“详细信息”，但不能通过静默截断使其不可访问。

## 4. 长文本、Tool 调用与 JSON 折叠规范

这是本轮最高优先级项之一。

### 4.1 当前问题

1. `ThreadDetail.tsx` 对所有消息使用 `m.content.slice(0, 4000)`，超过 4000 字符后**直接丢失，且没有截断提示或展开入口**。
2. Run 错误使用 `r.error.slice(0, 300)`，同样无法查看完整错误。
3. Tool 消息只保留 `role` 和 `content`，工具名称等上下文被规整过程丢弃，界面只显示原始 `tool`。
4. Tool 返回的大段 JSON 与普通消息一起铺展，没有结构摘要、格式化或折叠。
5. Fleet 操作助手虽然过滤了大多数 Tool 消息，但 Agent 最终回复若包含 JSON，仍会以原始文本显示，并在固定高度内部滚动。
6. `LoopOutput` 可能显示很长的交付全文；交付快照只有单行截断，主要依赖鼠标悬停查看。

### 4.2 建议的统一组件

新增纯展示层组件，例如 `CollapsibleContent` / `MessageContent`，由会话详情、操作助手、交付输出共同使用。只调整前端规整和渲染，不改变 Agent Tool 调用或 API。

**普通长文本**

- 超过约 1200 字符或 16 行时，默认显示前 8–12 行。
- 显示明确操作：`展开全文`、`收起`，并标注`共 36 行`或`约 5.2k 字符`。
- 不再使用无提示的字符串截断；完整内容始终可访问。
- 避免“卡片内部滚动＋页面滚动”的双层滚动。

**Tool 返回**

- 默认折叠，摘要是首要内容，而不是原始 JSON。
- 摘要优先显示：`工具名称 · 成功／失败 · 18 项 · 2.4 KB`。
- 当前数据若有工具名，应在规整视图模型中保留；没有时退化为`工具返回`，不要虚构名称。
- 展开后显示格式化 JSON；可提供`复制 JSON`。
- 工具参数与返回结果可分区为`参数`和`返回`，默认只展开返回摘要。

**AI 回复中的 JSON**

- 识别纯 JSON 与 ```` ```json ```` 代码块。
- 数组摘要显示元素数量；对象摘要显示顶层字段；无法解析时按普通长文本处理。
- 示例：`JSON 数据 · 18 项`，点击后查看完整内容。
- 对结构明确的操作结果，可先显示已有字段形成的简短结果摘要；原始 JSON 始终保留在折叠区。

**交付与错误**

- 交付正文长时折叠，但“采纳／退回”操作保持可见。
- 错误先显示一句可读摘要，完整堆栈进入`技术详情`。
- 不截断错误；不能只依赖 `title` 悬停查看完整内容。

### 4.3 内容表达建议

- AI 交付和回复建议使用安全的 Markdown 渲染，避免直接展示大量 `##`、表格符号和代码块标记。
- JSON、代码、普通说明采用不同容器，不全部使用 `whitespace-pre-wrap`。
- 文件路径在正文中仍保持可下载；折叠不能破坏现有产物链接。

## 5. 分页面 Review 与建议

## 5.1 任务首页 `/`

代码：`console/frontend/src/pages/Home.tsx`

### 主要问题

1. **根任务重复显示。** `PanelHead` 已显示根任务标题，`TaskNode` 紧接着再次显示同一标题、Task ID 和状态。
2. **状态过多且没有主次。** 同一卡片可能同时出现“待验收”“执行中”“待领取”，但没有说明哪个是用户动作状态、哪个是执行状态。
3. **状态命名不一致。** 筛选用“待确认”，卡片用“待验收”；`pool_status=done` 又统一映射为“已验收”，可能覆盖人工关闭的语义。
4. **创建任务区技术选项过重。** 执行 Agent、实例模型、Subagent 策略三个下拉与主按钮同级，新用户首先看到的是模型治理而不是任务本身。
5. **默认选项文案复杂。** `不入池指派 · 先放任务池`包含双重否定，需要用户解析。
6. **指标不够行动导向。** 当前突出总任务数、Agent 数、累计 Token，但首页默认任务是处理“待领取／待验收”。装饰刻度进一步增加噪声。
7. **输出与元数据重复。** 每个节点都展示 source、Token、时间、Loop、Thread、Agent 定义，长任务树会迅速失去重点。
8. **验收说明过长且交付默认展开。** `任何已识别的人或 Agent 均可验收`属于治理说明，不是每次验收都需要阅读的信息。
9. **反馈颜色有误。** `ReviewPanel` 的成功和异常都写入 `msg`，最后统一使用绿色展示，错误可能被表达为成功。

### 建议首屏结构

1. 页头：`任务看板`＋一个主按钮或创建面板，不再解释父子任务如何流动。
2. 创建面板：任务输入＋执行者＋主按钮；模型选项放入默认收起的`高级设置`。
3. 行动指标：优先显示`待领取`、`待验收`、`执行中`、`异常`；Agent 总数和 Token 降为次要信息。
4. 任务列表：筛选与数量一行；卡片先显示任务标题、主状态和结果，再显示少量元数据。
5. 技术链路：`Loop #`、`会话`、`Agent 定义`收进次要行或详情区。

### 推荐文案

| 当前 | 建议 |
|---|---|
| `任务实例看板` | `任务看板` |
| 页头整段父子任务说明 | 删除；需要时仅保留`点击任务查看执行与交付` |
| `发起任务实例` | `发起任务` |
| 输入框长 placeholder | `描述要完成的任务…` |
| `不入池指派 · 先放任务池` | `暂不指派` |
| `实例模型 · 系统默认` | `任务模型：系统默认` |
| `Subagent · 指挥官自动选模` | `Subagent：自动选模` |
| `Subagent · 全部继承此模型` | `Subagent：继承任务模型` |
| `放入任务池` | `创建任务` |
| `指派并发起` | `指派并创建` |
| `待确认` | `待验收` |
| `默认显示需要你行动的…` | 删除，选中筛选本身已表达 |
| `FINAL OUTPUT / 最终输出` | `最终交付` |
| `CURRENT OUTPUT / 当前输出` | `最新输出` |
| `尚未产生执行轮次` | `尚未领取`或`尚未执行`，按真实状态选择 |
| `等待 Thread 启动` | `等待会话启动` |
| `任何已识别的人或 Agent 均可验收` | 删除或移至验收说明图标 |
| `采纳这份` | `采纳交付` |
| `退回意见（对方在同一会话中续跑修正）` | `填写退回原因；对方将在原会话中修改` |

### 呈现调整

- 根任务标题只出现一次；子任务保持树形缩进。
- 每张卡只保留一个主状态；执行状态需要保留时，以弱元数据展示。
- `待领取／待验收`使用 amber，正在执行使用绿色；不要同时闪烁多个标签。
- 移除指标装饰刻度。
- 输出预览最多 3 行的策略可以保留，但应提供完整内容入口，JSON 走统一折叠组件。
- 退回输入框可在点击“退回”后展开，避免每份交付长期占据大块操作区。
- 成功与错误反馈拆分，错误不得使用绿色。

## 5.2 Agent 列表 `/registry`

代码：`console/frontend/src/pages/Registry.tsx`

### 主要问题

- 页头同时解释注册、配置、停止、拉起、任务页和会话页，属于导航说明而非当前任务。
- 注册表单完全依赖 placeholder，输入后字段身份消失。

## 6. 共享组件专项建议

### `Panel.tsx` / `index.css`

- 区分装饰性丝印与功能面板标题，重要标题不再统一使用 10px `silk`。
- 减少所有卡片四角螺丝、边框、LED 同时出现造成的视觉竞争；装饰不能强于任务标题。
- 保留现有机架仪器风格，但让样式服务于信息层级，而不是所有模块同样重量。

### `Status.tsx` / `statusMeta.ts`

- 所有已知状态从同一文案表读取，Task 详情和 Registry 不再直接显示原始值。
- 状态颜色与 blink 统一；只让真正正在运行的状态闪烁。
- 对未知原始状态可显示`未知状态`，原值放技术详情，避免界面随机出现英文。

### `LoopOutput.tsx`

- 当前主显 `latest_output`，但标题始终为`交付内容`，容易把后续最新回复误认为交付快照。
- 建议明确区分：`最新输出`与`交付快照 vN`；只有确认交付语义时才显示`最终交付`。
- 快照不要只单行截断，改为可展开的审计信息。
- 长输出和 JSON 使用统一折叠规范。

### `ArtifactText.tsx` / `LinkifyText.tsx`

- 保持现有产物下载能力。
- 文件路径和长 URL 需要断行或省略策略，链接文本不能撑破消息卡。
- 链接颜色纳入全站色彩规范，不再单独引入天空蓝。

### 错误、空态与加载

建议共享三种基础表达：

- 加载：`正在加载任务…`
- 空态：`暂无任务`，附与当前页面相关的一句行动提示
- 失败：`任务加载失败`，附`重试`与可展开`技术详情`

禁止把请求失败直接等同于空数据，也不要默认把端口、网关名和完整异常放在主文案中。

## 7. 优先级与实施顺序（确认后再改）

### P0：先修正会误导或丢失信息的表达

1. 取消消息与错误的静默截断，提供完整内容展开。
2. 建立 Tool／JSON／长文本统一折叠组件。
3. 修正首页验收、会话验收、模型连接测试的错误颜色。
4. 统一`待领取／待验收／已退回`等核心状态；区分已验收与已关闭。
5. 区分`最新输出`与`交付快照`，避免错误标注。
6. 修正任务详情无 Loop 时的矛盾引导。

### P1：完成主路径降噪

1. 首页去除根任务重复，创建区高级选项折叠，指标改为行动导向。
2. 会话详情与任务详情重排信息层级，技术元数据默认弱化。
3. 全站标题、导航、状态、按钮、时间和 ID 采用统一规范。
4. Registry 与 Settings 表单增加持久标签，清理开发文档式说明。
5. 会话列表减少默认技术列，强化会话标题与状态。

### P2：统一视觉细节

1. 面板标题字号、链接样式、状态颜色和 blink 规则。
2. 登录、回调、空态、错误、加载反馈统一。
3. 清理重复刷新提示、装饰刻度和非必要模块编号。

## 8. 验收标准

后续修改完成后，应至少满足：

- 所有现有路由、按钮、API 调用和业务状态流转保持不变。
- 首页同一根任务标题不再重复，默认首屏能直接识别待领取、待验收和异常。
- 全站同一状态不再出现多种中文名称，不再把已关闭统称为已验收。
- 任何消息、交付和错误都不会因为前端 `slice` 而无法查看全文。
- Tool 返回和 JSON 默认有简洁摘要，展开后内容完整、格式可读。
- 长内容不会形成多层内部滚动，展开／收起不影响现有下载链接。
- 错误不会显示为绿色；所有页面错误、成功、警告颜色一致。
- Registry、模型和 PAT 表单在输入后仍能识别字段名称。
- 详情页不再以`水合`、`agents_api`、`人机共用协议`等内部术语作为主要说明。
- 现有前端测试继续通过；为折叠、完整内容查看、状态文案和反馈颜色补充必要测试。

## 9. 本轮边界

本报告不建议改变：

- Task → Loop → Thread 的业务模型。
- Agent 注册、配置、停止、拉起、销毁逻辑。
- 任务创建、领取、交付、采纳、退回、重试与断点续跑逻辑。
- 模型配置、凭证轮换、PAT 签发与吊销逻辑。
- Fleet 操作助手的 Tool 调用和写操作确认协议。

所有建议均限于：**命名、文案、层级、样式、信息分区和内容折叠。**
