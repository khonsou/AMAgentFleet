# Agent Fleet 游戏表现层 PRD

- 日期：2026-10-30
- 状态：待评审
- 范围：B 页面的纯游戏化状态表现与入口，不定义 Fleet 业务规则
- 业务依赖：`docs/prds/2026-10-30-fleet-project-prd.md`

## 1. 产品目标

把 Agent Fleet 表现为一片持续运转、可扩展的草地，让用户不看表格也能感知：

- 哪些 Agent 正在工作、空闲、等待或遇到异常；
- 每个 Agent 正在参与哪些 Task；
- Task Pool 中有哪些新工作与待处理事项；
- 哪些长期 Project 正在推进，最近产生了什么交付。

B 负责状态感知、生命力和入口；完整对话、验收、配置与文件管理仍由 A1 或后续 Project 页面承担。

## 2. 体验原则

1. **按用户心智表达，不暴露实现分层**：不在主画面要求用户理解 LOOP、Thread、checkpoint 或竞争执行。
2. **一个元素只有一个主要含义**：避免桌子同时代表工位、Project 和文件目录。
3. **动作表达状态变化**：移动与动画来自真实事件，不做无意义的随机忙碌。
4. **主画面保持轻量**：详细信息通过游戏内浮窗或跳转查看，不把 B 做成另一张数据表。
5. **空间可持续扩展**：Agent、Task 与 Project 增加时扩展草地和视野，而不是无限缩小人物。

## 3. 游戏元素映射

| 游戏元素 | 用户语义 | 表现要求 |
|---|---|---|
| 小人 | Agent | 稳定身份与外观；一个人物可同时参与多个 Task |
| Task 气泡 | 一场 Task 群聊 | 显示简短状态；点击直接进入群聊 |
| 气泡中的 OUTPUT | 群内交付 | 交付、退回与再次交付都是 Task 内事件 |
| 大屏 | Task Pool | 展示新 Task、待领取与待处理事项，不承担完整详情 |
| 会议桌 | 长期 Project | 多个 Task 的协作场所，持续积累上下文与交付 |
| 桌上资料 | Project 共享上下文与交付积累 | 用轻量视觉增长表达积累，不直接展示文件正文 |
| 草地休息区 | Agent 空闲状态 | 无活跃工作时自然休息，不固定坐在电脑前 |
| 电脑等道具 | 工具活动的视觉反馈 | 只表达正在执行，不代表独立业务对象 |

不再设置独立的“指挥官交付区”：OUTPUT 在 Task 群聊中交付，不需要人物把文件送到另一个业务场景。

## 4. 场景结构

### 4.1 全局草地

- 保留无限扩展、平移、缩放、云和飞鸟。
- 默认视野优先看到 Task Pool、当前活跃 Agent 与最近活跃的 Project 会议桌。
- 新区域按需出现，避免一开始摆放大量无业务含义的装饰。

### 4.2 Task Pool 大屏

- 是全局任务入口，不是 Project 的替代品。
- 只突出新出现、待领取、等待人和异常等重点。
- 点击大屏条目，高亮相关 Agent 或 Project；再次操作进入 A1。
- Agent 不需要长期围在大屏旁；只有状态变化需要时才产生移动或注意动作。

### 4.3 Agent 与 Task 气泡

- 一个人物可以有多个 Task 气泡。
- 默认展示最活跃或最需要处理的 1–3 个，其余合并为 `+N`。
- 气泡内容使用用户语言，例如“等待指导”“正在整理”“OUTPUT 已交付”。
- 点击气泡进入对应 Task 群聊；多执行分支由界面内部处理，不在游戏主画面拆成技术对象。
- 点击人物打开轻量浮窗：当前状态、Task 列表与异常摘要。

### 4.4 Project 会议桌

- 只有 Fleet Project 业务能力落地后才正式启用。
- 一个 Project 对应一张会议桌，不对应单个 Task。
- 当前参与该 Project 的 Agent 可以围绕桌子工作；人员随 Task 状态变化加入或离开。
- 桌上以书本、文件或光点等轻量元素表达共享资料与交付积累。
- 新 OUTPUT 被采纳时，桌上出现短暂的积累动画；未采纳结果不增加正式积累。
- 点击会议桌打开游戏内浮窗：Project 状态、活跃 Task、最近 OUTPUT 与待处理事项。
- 浮窗提供进入 Project 页面的入口；完整资料和交付管理不在 B 内重造。

## 5. 状态驱动动线

### 5.1 独立 Task

1. Task Pool 出现新 Task。
2. 相关 Agent 头上出现 Task 气泡。
3. Agent 进入工作状态，气泡随群聊进展变化。
4. OUTPUT 交付时气泡出现交付反馈。
5. 验收后气泡完成并消退；退回时同一气泡转为待修正。
6. Agent 没有其他工作时回到休息状态。

### 5.2 Project Task

1. Project 会议桌出现新的 Task 活动。
2. 相关 Agent 来到会议桌附近，头上出现 Task 气泡。
3. 编排、指导与 OUTPUT 均归入该 Task 群聊，不在主画面拆成多个技术层级。
4. OUTPUT 被采纳后，桌上增加交付积累。
5. Task 完成后，无其他 Project 工作的 Agent 离开会议桌。

### 5.3 等待与异常

- 等待人指导：气泡突出等待状态，必要时人物做出注视或提示动作。
- 执行异常：人物与对应气泡出现异常标识，不通过随机走动表达。
- 退回修正：沿用同一人物与 Task 气泡，不能表现为换了新任务。

## 6. 交互边界

允许：

- 平移、缩放与聚焦。
- 点击人物、Task 气泡、Task Pool 和 Project 会议桌。
- 查看轻量状态浮窗。
- 跳转 Task 群聊、A1 或 Project 页面。

不重复实现：

- 完整群聊与消息流。
- OUTPUT 全文阅读与并排验收。
- Project 说明编辑与文件管理。
- Agent 配置、模型选择和权限管理。
- LOOP／Thread 技术详情。

## 7. 视觉反馈优先级

1. 需要人处理的等待与异常。
2. 新 Task 与新 OUTPUT。
3. 当前正在运行的 Agent 与 Project。
4. 已完成和空闲状态。

游戏动效不得让完成、空闲等低优先级状态抢占注意力。云、飞鸟与环境动画保持缓慢，不与业务提示争夺视觉焦点。

## 8. 规模与扩展

- Agent 增加：扩展草地活动区域，不复制同一人物表达多个 Task。
- Task 增加：气泡折叠为 `+N`，详细列表进入浮窗。
- Project 增加：新增会议桌并扩展相机可探索范围。
- 长期积累增加：只改变桌面视觉丰富度与数量摘要，不无限增加实体文件。
- 大量对象下优先渲染视野内动画，远景只保留状态标识。

## 9. 实施顺序

### B1：不依赖 Project 的基础版本

- Agent 小人。
- 多 Task 气泡。
- Task Pool 大屏。
- 真实状态驱动的移动与反馈。
- 点击进入 Task 群聊或 A1。

### B2：Project 能力落地后的扩展

- Project 会议桌。
- Project 参与者与活跃 Task 表现。
- 共享上下文与正式交付的积累动画。
- Project 浮窗与业务页面入口。

B1 不得先以 dummy Project 数据反向定义业务；B2 使用的第一份 PRD 确认后的 Project 语义。

## 10. Dummy Data 验收场景

原型至少覆盖：

1. 一个 Agent 同时有三个 Task，主画面只突出重点气泡。
2. 一个独立 Task 从创建、执行、交付到退回再完成。
3. 一个 Project 下有多个 Task 和多个 Agent，OUTPUT 采纳后桌面积累增加。
4. 一个 Project 已归档，会议桌仍可见但不再出现新工作。
5. 一个 Agent 异常，另一个 Agent 等待人指导，两者优先级清晰。
6. Project 与 Agent 数量增加后，相机扩展且人物大小仍可辨认。
7. 所有详情入口均可用，主画面不出现 LOOP／Thread 术语。

## 11. 验收标准

- 不看任何说明，用户能指出 Agent、Task、Task Pool 与 Project 分别是什么。
- 用户能把一个 Agent 的多个 Task 与一个 Project 下的多个 Task 正确区分。
- 用户能通过气泡进入正确 Task 群聊。
- OUTPUT 在 Task 内交付，正式积累在 Project 中可见。
- 动画与真实状态一致，没有随机领取、随机交付或错误换人。
- B 不承载 A1 的详细信息展示职责。
- Project 会议层在业务 PRD 未落地前不作为已完成能力对外呈现。
