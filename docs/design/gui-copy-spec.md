# GUI 文案规范速查表（review checklist）

> 一页速查，权威来源是 [concept-model.md](concept-model.md)（§4 词表 / §4.1 眉标规范 / §6 决策记录）。
> 本表只做提炼与加禁例，与之冲突时以 concept-model.md 为准。
> **任何 UI 改动合并前逐条打勾。**

## 黄金规则（3 条）

1. **词表唯一**：界面上的每个词必须能在 §4 词表找到；想造新词，先改词表再改界面。
2. **编号必带实体标签**：禁止裸 `#N`。编号前必须是 `task #` / `loop #` / `TASK #` 等实体词——编号旁边出现 agent 名时尤其容易误读。
3. **装饰词须过审**：眉标、面板副标、统计标签也是用户会读到的词（UNIT 事件教训）。MODULE 编号是唯一的免检装饰（机架设计语言，纯导航顺序位）。

## 标准词速查

| 界面写法 | 禁止写成 |
|---|---|
| 任务 task | 单、需求、需求单 |
| 执行轮次 loop（口语「一次执行」） | 任务、重试 |
| 会话 thread | **对话**、session、对话记录 |
| 任务池 task pool | **任务流**、TASK STREAM |
| 运行 run | 对用户露出仅限观测页 |
| 认领 claim（人/agent 同词） | 接单、抢单 |
| 指派 assign | 认领（两者不同） |
| 交付 deliver / 验收 accept·return | 提交/通过/驳回 |
| 发起 create | 派发（dispatch 仅指「发起并指派给某 agent」） |

## 页头版式（§4.1，四行固定）

```
← <返回链接>
MODULE NN / <模块名>            ← 纯模块名，不带实体后缀
<概念层级 breadcrumb>           ← 仅当有父级时渲染
<h1 实体标题>
```

- breadcrumb：词表实体大写形式，分隔符 `›`，编号低调、内容为主、截断 + `title` 悬浮。
- 可点击性：有独立详情页的段（TASK）= 链接；寄居页段（LOOP）= 链接到寄居页锚点 `/tasks/:id#loop-N`；当前页段 = 纯文本。
- 链顶实体（agent 定义）不硬造 breadcrumb；数据缺失（自由 thread）整行消失，`null` 是语义不是错误。

## 编号与链接文案约定

| 场景 | 写法 | 示例 |
|---|---|---|
| breadcrumb 内 | 大写实体词 | `TASK #159 › LOOP #187 › THREAD` |
| 卡片/行内 meta | 小写实体词 | `task #156 · web`、`loop #187` |
| thread 链接（统一一种） | `会话 {8位id} →` | `会话 d80a2e61 →` |
| 计数标签 | 实体词全大写 | `1 LOOPS`、`N AGENTS` |

## 禁例清单（踩过的坑）

- ❌ `UNIT 01 / TASK DETAIL` —— 无概念对应的装饰词
- ❌ `查看对话 →` —— 非标准词 + 无 id
- ❌ `fleet-cmd-01　#156 · web` —— 裸编号挨着 agent 名（读成 agent 编号）
- ❌ `任务流 / TASK STREAM` —— 任务池的可视化误命名
- ❌ 详情页眉标 `· TASK` / `· AGENT` 后缀 —— 实体身份归 h1/breadcrumb
- ❌ 同一实体三种链接文案并存 —— thread 链接全站只能有 `会话 {8位id} →` 一种

## Review Checklist（PR 前逐条核对）

- [ ] 新增/修改的每个界面词都能在 §4 词表找到（或词表已先更新）
- [ ] 全站无裸 `#N`（grep `#{` 逐个确认带实体前缀）
- [ ] 无「对话 / 任务流 / 派发(=发起) / 重试(=loop)」等禁用词
- [ ] 页头符合四行版式；MODULE 行无实体后缀
- [ ] 新增详情页有 breadcrumb 且段可点击性符合 §4.1（含寄居锚点）
- [ ] thread 链接文案为 `会话 {8位id} →`
- [ ] 概念文档 §6 已追加本次决策记录（含反转旧决策的理由）
